# 相对论飞行与背景星空：核心特色、实现与取舍

这一篇解释产品最有辨识度的部分：观众在飞行过程中看到的星空，为什么会改变方向、颜色和亮度，以及这些变化怎样在浏览器里实现。

## 1. 什么是本项目的创新点

这里的“创新”指产品设计和工程组织。相对论公式来自既有物理，本项目没有提出新定律，也没有证明它在同类产品中是首次实现。

本项目把三种变化组合在同一段可操作的飞行里：

| 变化 | 观众看到什么 | 程序依据 |
|---|---|---|
| 光行差 | 原来位于侧面的星光，所见方向更靠近运动前方 | 观察者与星空之间的方向变换 |
| 多普勒近似调色 | 不同观察方向的星光出现不同色调变化 | 多普勒因子与近似色温调制 |
| 辐射亮度演示 | 前向星光增亮，后向星光变暗 | 按方向计算的 D⁴ 增益 |

它们共用 β 和运动方向。因此，改变速度参数会同时改变方向反查、多普勒倍数和亮度，而不是只触发某个预制动画。开启与关闭相对论的对照，让观众可以把变化与原因联系起来。

第二个特点是把相机朝向与移动方向分开。飞行时镜头会转向目标，但相对论效应取决于运动方向。程序根据相机本帧的位置变化确定运动轴，再转换到相机坐标中计算。这个安排保留了两者的区别。

第三个特点是把有限距离天体与无限远星空分层。行星保持可辨认，星空承担相对论观察实验。对于教学网页，这能把注意力放在星光变化上，也避免把尚未实现的完整相对论成像混入演示。

第四个特点是可交付的轻量实现：星空不依赖外部星图或图片，启动时生成并保存；之后由显卡对每个像素反查方向。配套检查执行实际 GLSL，而不只验证一份相似的数学代码。

## 2. 光行差：星星没有搬家，观察方向变了

“光行差”描述运动状态改变后，星光的所见方向发生变化。可以先借助雨的直觉：站着和跑着时，你会觉得雨迎面落下的方向不同。光的情况需要狭义相对论计算，不能直接套用普通雨滴的速度相加。

本项目把方向定义为“从观察者看向星光来源”。这与光子朝观察者飞来的方向相反。符号约定错了，前方效果就会变成后方效果。

假设静止星空中某束星光位于运动方向的侧面，也就是 90°。当 β=0.98 时，它在运动观察者眼中的方向约为 11.48°，更靠近前方。光行差和多普勒的基础物理可参考 [MIT 相对论课程第六讲](https://ocw.mit.edu/courses/8-033-relativity-fall-2006/909e205adee074e5401e0a7c7cce06c0_lecture6_kinem3.pdf)。

这不表示所有恒星都跑到同一个点，也不表示飞船创造了一个硬边界的光锥。屏幕视角、观察方向与速度共同决定哪部分星空进入画面。

## 3. 为什么程序从屏幕像素“往回查”

有两种思路。第一种是把每颗恒星变换后放到屏幕上。第二种是从屏幕每个像素出发，问“我现在看向这里，对应静止星空的哪个方向”。

项目选择第二种，也就是逆映射。它类似通过一面会改变光路的镜片看一张全景图：每一个屏幕位置都能找到应当读取的星空方向。

程序先从像素位置、视场角和屏幕宽高比重建一条观察射线，再用完整三维逆洛伦兹变换得到静止星空方向。变换必须同时处理沿运动方向的分量和横向分量，不能只改一个坐标后再归一化。

关闭相对论时，速度参数设为 0，但每个像素仍有自己的观察方向。因此对照组显示完整天空；若把所有像素都指向同一个方向，画面就只剩同一块颜色，那不是有效的对照。

方向公式和逐像素流程在 [公式读本](06-公式读本.md) 中给出；接手 agent 应查看实际使用的 shaders.js，而不是另写一份未接入画面的公式。

## 4. 多普勒：颜色变化为什么只能近似展示

多普勒因子 D 表示观察到的光频率相对原频率的倍数。D 大于 1 对应频率提高，D 小于 1 对应频率降低。

β=0.98 时，正前方的 D 约为 9.95，正后方约为 0.1005。对应波长关系为 λ观察=λ原始/D。真实光谱在极大移位时可能越过可见光范围，不能简单理解为“任何星星都变成肉眼可见的蓝色或红色”。

项目只保存 RGB 颜色，没有保存每颗星完整的光谱。初始星色来自不同的近似色温；飞行后，shader 用 5800 K 作为统一参考，对 RGB 施加近似色温比例，而不是把每颗星的原始色温精确乘以 D 后重新积分光谱。

这个方法可直观表达冷暖变化，计算和存储较轻。代价是它不能准确回答某颗真实恒星在这种速度下对人眼究竟是什么颜色。温度还被限制在 1000 至 40000 K 的拟合范围内，超出部分不会继续按真实光谱延伸。

## 5. 亮度：为什么不能直接把理论值显示出来

对按全部频率积分的辐射亮度，相对论变换可以给出 D⁴ 关系；实际人眼或相机只接收部分波段，不能把这个关系直接等同于可见光照片的每颗恒星总亮度。[马里兰大学辐射过程讲义](https://pages.astro.umd.edu/~mcmiller/teaching/astr601f15/lecture02.pdf) 区分了频率积分亮度、波段观测和通量。

项目把 D⁴ 应用于天球纹理的线性 RGB，作为亮度演示。β=0.98 时，正前方增益约为 9801，正后方约为其倒数，二者比值约为 9600 万。普通屏幕无法按这些倍数直接发光。

因此先用 HDR 尽量保存中间亮度，再用 ACES 形式的映射压缩。你看到的是适合屏幕的表达，不能把最终像素亮度拿来测量真实辐射强度。8 位降级目标的范围更窄，会更早损失高光细节。

## 6. 背景星星怎样生成

太阳系页的背景包含 12000 个星点：8000 个分布在整片天空，4000 个集中于一条倾斜的带状区域，形成银河带的视觉印象。

普通星点使用球面面积较均匀的方向采样。程序没有简单地把经纬度都均匀取值，因为那样会在两极堆出过多点。银河带则沿一条大圆分布，用几次随机数的叠加形成较集中、两侧渐淡的纬度分布。

这是一片程序生成的示意天空，没有对应真实星表、星座位置、观测地点或日期。银河带倾斜方向也由设计参数指定，不是某个地面地点看到的真实银河位置。

随机序列的种子固定为 20261013。它让同一版本的初始天空保持稳定，便于对照和排查；它不代表使用了当天的天文观测资料。以后改变算法或种子会改变背景布局。

每个星点还获得近似色温、大小和亮度。亮度通过幂律分布形成“多数较暗、少数较亮”的层次；银河带整体更小、更暗，避免把背景铺成一条抢眼的亮墙。

显卡把每个星点画成柔边小圆：中心较强，边缘逐渐减弱，圆外不绘制，再用加法叠加。这个形状是视觉设计，并非望远镜衍射图案或恒星真实表面的大小。

图鉴页使用另一套 CSS 装饰星空，服务于阅读氛围，不承担相对论实验。不能把图鉴的背景规则当作太阳系天球的实现。

## 7. 为什么放在球壳上，却当作无限远

程序先把星点放在半径 500 的球壳上，这是便于绘制的一种容器。相机在世界原点向六个方向拍下它，后续只按方向读取结果。

因此，“半径 500”是绘制参数，不是恒星距离。飞行时不会根据相机与球壳的几何距离去产生恒星视差，也不把观众飞出球壳作为旅程效果。

视差指移动观察位置后，附近物体相对远处背景改变位置。在这个压缩太阳系的教学场景里，把恒星背景看作无限远有助于突出方向变化。代价是没有真实恒星距离、位置运动和传播时延。

## 8. 六面立方体纹理是什么，为什么用它

可以把相机想成坐在一个盒子中间，分别拍向前、后、左、右、上、下。六张图合在一起覆盖整个天空，这就叫 cubemap，中文可称立方体贴图。

每个面是 1024×1024 像素。它保存在显卡里，不是六张需要下载的图片。初始化时绘制一次后保持世界方向固定；观众转头时，程序旋转读取方向，而不是把天空重新拍一遍。

这种表示天然接受三维方向作为查询条件，与相对论逆映射的输出相匹配。它也避免了长方形全景图在极区的强烈拉伸，但不是没有代价：立方体面边界、有限分辨率和高速放大区域仍可能出现采样细节问题。

半浮点 RGBA 的六面纹理，仅颜色存储的名义大小约为 48 MiB；8 位版本约为 24 MiB。这不包含屏幕目标、几何和驱动额外开销，也不是测得的总显存用量。更高分辨率会增加内存和初始化成本，本版选择 1024 作为观看细节与成本之间的折中。

## 9. 为什么没有选其他方案

| 方案 | 有什么优势 | 本项目的选择理由与代价 |
|---|---|---|
| 平面图片或 CSS 星点 | 简单、适合阅读背景 | 图鉴采用 CSS；太阳系需要全方向采样，因此使用天球 |
| 长方形全景图 | 便于制作和储存整片天空，也可以支持方向映射 | 同样可行；本版选立方体贴图，让三维方向读取更直接 |
| 每帧逐颗变换三维恒星 | 可携带每颗星的温度和独立数据 | 本版保存成纹理，减少重复绘制；损失单星完整光谱信息 |
| 真实星表与光谱资料 | 可以对应真实恒星与观测任务 | 本版面向概念教学，选择程序天空，减轻资料、网络与授权整理工作 |
| 每帧重新捕获六面 | 适合本身会变化的天空 | 当前天空静态，只启动时捕获；动态天空需要另行更新 |
| 同时变换所有行星影像 | 有望构成更完整的相对论视觉模拟 | 需要光传播时延、有限距离几何等额外模型，当前不包含 |

这些方案不是一份优劣排名。如果产品以后改为真实星座识别或完整航行模拟，选择也应随目标变化。

## 10. 飞行时间与物理边界

默认一程镜头为 20 秒，峰值 β 为 0.98。β 按飞行进度平滑上升再下降，用于控制视觉实验。镜头空间路径采用另一条缓入缓出曲线，两者没有按真实距离和加速度绑定。

HUD 的演示 Δτ 累加 dt/γ，表达演示速度曲线下的时间积分。参考显示距离 4.4836 AU 的 37.29 分钟下限，只是 L/c 的公式示例，不能解释为这次 20 秒飞行完成了真实航程。

太阳与行星没有进行相对论再投影、光传播时延、相对论视觉旋转或引力透镜计算。程序保留了一个独立的真实加减速剖面函数用于数值工具与测试，但它没有接入当前镜头。

讲解时可以突出可操作的多效应联动、方向反查和分层设计，同时保留这些边界。这样既能说明特色，也不会让观众误以为画面是一段严格物理航行的记录。
