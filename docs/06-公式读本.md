# 公式读本：符号是什么意思，画面用它做什么

不需要逐条计算这一篇。先看每节的用途和例子；公式供你核对讲解，也让接手开发者能找到代码依据。

标注“物理关系”的公式来自已有模型；“显示或动画规则”是本项目选择的表现方式。二者不能混用。

## 1. 速度比例 β：飞得多接近光速

**类型：物理量定义；页面中的数值是演示参数。**

~~~text
β = v / c
c = 299792458 米/秒
~~~

v 是速度，c 是光速。β=0.6 表示数值相当于光速的 60%；默认峰值是 0.98。程序要求 β 小于 1，因为到达 1 时部分公式会发散。

页面并没有把镜头走过的显示距离除以时间来计算真实 v。它把 β 单独作为星空变化的控制参数。

代码位置：rel.js 的 clampBeta，solar-app.js 的 betaPeak 和飞行进度。

## 2. 洛伦兹因子 γ：时间关系变化到什么程度

**类型：物理关系。**

~~~text
γ = 1 / √(1−β²)
~~~

√ 表示平方根。γ 在静止时为 1，接近光速时增长。计算时用 (1−β)(1+β) 替代 1−β²，改善接近上限时的数值稳定性。

| β | γ，约值 | 正前向多普勒 D，约值 | 原来侧向 90° 的星光所见角度 |
|---:|---:|---:|---:|
| 0 | 1 | 1 | 90° |
| 0.6 | 1.25 | 2 | 53.13° |
| 0.9 | 2.29 | 4.36 | 25.84° |
| 0.98 | 5.03 | 9.95 | 11.48° |

γ 不是镜头的缩放倍数。它参与多普勒与演示时间积分。

代码位置：rel.js 的 gamma。

## 3. 光行差：运动后看见的方向

**类型：物理关系。**

θ源 是静止星空中的来向与运动方向的夹角；θ观察 是运动观察者看到的夹角。两种角度都从运动前方量起，且“来向”指看向星光来源的方向。

~~~text
cos(θ观察) = [cos(θ源)+β] / [1+β·cos(θ源)]
cos(θ源) = [cos(θ观察)−β] / [1−β·cos(θ观察)]
~~~

cos 是余弦函数，用于把角度转换成便于计算的方向分量。若 θ源=90°，余弦为 0，第一式便得到 `cos(θ观察)=β`。β=0.98 时对应约 11.48°。

第一式描述星光从哪里移到所见位置；第二式反过来告诉屏幕像素应该读取静止天球的哪里。渲染采用第二种思路，但实际需要完整三维向量，见下一节。[MIT 第六讲](https://ocw.mit.edu/courses/8-033-relativity-fall-2006/909e205adee074e5401e0a7c7cce06c0_lecture6_kinem3.pdf) 讨论角度变换和多普勒；不同资料使用光子传播方向时，符号可能与这里相反，须先核对约定。

代码位置：rel.js 的 aberrateCos、unaberrateCos，以及 shaders.js。

## 4. 完整三维逆变换：不能只改一个坐标

**类型：物理关系在渲染中的表达。**

d 是屏幕像素的单位观察方向，a 是单位运动方向。单位方向向量只是一个长度为 1 的方向箭头。点积 d·a 给出二者夹角的余弦，记作 μ。

~~~text
μ = d·a
denom = 1−βμ
横向部分 = (d−aμ) / (γ·denom)
纵向部分 = a·(μ−β) / denom
源方向 = normalize(横向部分 + 纵向部分)
~~~

normalize 表示把方向箭头调整为长度 1，不改变其指向。横向与纵向分量都要变换，才能得到正确源方向。

shader 还把相机中的源方向旋转到固定的世界方向，再读取立方体天球。CPU 纯函数与 GPU shader 分开验证，避免同一错误在测试和画面中互相印证。

代码位置：rel.js 的 unaberrateDirection、shaders.js 的 dSource。

## 5. 从像素重建射线：屏幕位置怎样成为方向

**类型：相机几何。**

x 和 y 是像素在屏幕中的位置，转换后范围为 −1 到 1；A 是画面宽高比，f 是竖直视场角，默认 30°。

~~~text
d = normalize([x·A·tan(f/2), y·tan(f/2), −1])
~~~

tan 是正切函数，它把视场角与屏幕平面宽度联系起来。−1 表示该相机以 −Z 为前方。左上角与正中央产生不同射线，因此必须逐像素计算。

代码位置：shaders.js 的 ndc 与 d；FOV_DEG 在 solarsystem.js。

## 6. 多普勒 D：光频率改变的倍数

**类型：物理关系；RGB 表现是近似。**

μ观察 是观察方向与运动方向夹角的余弦，范围为 −1 到 1。

~~~text
D = 1 / [γ·(1−β·μ观察)]
频率观察 = D·频率原始
波长观察 = 波长原始 / D
正前方：D = √[(1+β)/(1−β)]
正后方：D = 1 / 正前方D
~~~

θ观察=0° 时 μ观察=1，即正前方；180° 时为正后方。前后向 D 的乘积为 1，是一项有用的检查条件。

项目用近似函数 kelvin 将色温转成 RGB，实际飞行调色为：

~~~text
色温参考 = 5800 K
调色比例 = kelvin(5800·D) / kelvin(5800)
星空RGB = 原采样RGB · D⁴ · 调色比例
~~~

这不是每颗星的真实光谱变换。函数限制色温范围，并对过小分母作保护；“原采样 RGB”也已经是多颗程序星点生成的纹理数据。

代码位置：rel.js 的 doppler，shaders.js 的 D、kelvin 和 tint。

## 7. D⁴、合成与 ACES：怎样把亮度送到屏幕

**类型：辐射亮度关系加显示规则。**

对全频率积分的辐射亮度，D⁴ 是相应变换关系；项目把它用于线性 RGB 的教学表达。[马里兰大学讲义](https://pages.astro.umd.edu/~mcmiller/teaching/astr601f15/lecture02.pdf) 也说明，限定波段的观察与全频率积分不能直接等同。

~~~text
亮度增益 = D⁴
合成颜色 = 星空颜色·(1−α) + 主场景颜色
ACES(x) = clamp([x·(2.51x+0.03)] / [x·(2.43x+0.59)+0.14], 0, 1)
~~~

α 是主场景写入的覆盖度，无实体背景为 0。主场景颜色包含绘制时的混合结果，不能把上式机械套到任意未经处理的图片层。

x 是一个线性颜色通道的输入。clamp 表示把结果限制在 0 到 1。ACES 形式的近似映射压缩高光，之后只做一次 sRGB 输出编码。屏幕的最终亮度不是原始辐射亮度。

代码位置：rendering.js 的 renderScenePass，shaders.js 的合成、aces 和 encodeSRGB。

## 8. 演示速度、镜头进度和 Δτ

**类型：演示动画规则与物理时间关系的教学使用。**

u=t/T 是飞行进度，T 是本次起飞保存的演示时长。

~~~text
β(u) = β峰值·sin(πu)
F(u) = 4u³                         当 u<0.5
F(u) = 1−(−2u+2)³/2                当 u≥0.5
位置 = (1−F)·起点 + F·当前目标点
Δτ ≈ Σ [dt / γ(β)]
~~~

Σ 表示把每一小段时间相加。速度演示曲线与镜头位置曲线分别控制，不由真实距离共同求解。端点 β 显式设为 0，避免浮点残差。

朝向通过四元数 slerp 平滑插值。这是一种处理三维旋转的方法，不是新的物理量；它帮助镜头转向时保持连续。

关闭相对论时，时间积分按 β=0 对照处理。因此 HUD 里的 Δτ 要称“演示 Δτ”，不能宣称它是当前真实航程的飞船钟读数。

代码位置：rel.js 的 displayBetaAt，solar-app.js 的飞行分支。

## 9. 光速下限与尚未接入镜头的工具

**类型：物理下限与独立理想模型。**

~~~text
最短光传播时间 = L/c
~~~

L 是一程真实距离。4.4836 AU 换算后约对应 37.29 分钟。页面拿缩放后坐标差构成这一参考数值，只做示例；它不是当前镜头真实走过的航程。

rel.js 另有 trueProfile，针对一程“前半程恒定固有加速度、后半程对称减速”的理想模型。设 T>L/c：

~~~text
x = L/(cT)
η = 2·atanh(x)
β峰值 = tanh(η)
γ峰值 = cosh(η)
τ半程 = (T/2)·η/sinh(η)
固有加速度 = ηc/τ半程
一程固有时 = 2τ半程
~~~

tanh、cosh、sinh、atanh 是双曲函数；η 是快度，可理解为便于相对论计算的一种速度参数。该函数接受真实距离和时间，返回理想模型结果，越界返回 null。当前页面没有用它驱动镜头，不能把“函数存在”当作“产品已经实现”。

## 10. 轨道、压缩与抵达构图

**类型：参考轨道关系与教学显示规则。**

设 a 为参考半长轴，e 为偏心率，P 为公转周期，M₀ 为人为给定的初始相位。模拟时间按 20000 倍推进：

~~~text
M = M₀ + 2π·t模拟/P
M = E−e·sin(E)
u轨道 = a·[cos(E)−e]
v轨道 = a·√(1−e²)·sin(E)
真实参考半径 r = √(u轨道²+v轨道²)
~~~

M 是匀速增长的平均相位，E 是为计算椭圆位置而引入的中间角度。程序迭代解第二式，再由两个轨道分量得到平面位置，最后加入倾角。计算时必须把时间与周期换成同一单位。

显示规则为：

~~~text
距离显示数值 = [以AU计的真实参考距离数值]^ED
行星显示直径 = BASE·视野跨度·(R/R地球)^ER
默认：ED=0.5，ER=0.45，BASE=0.006
太阳显示直径 = 0.045·视野跨度
~~~

R 是行星参考半径。默认平方根距离映射压缩远近差异，尺寸幂律压缩大小差异。它们保持顺序，改变比例；径向压缩也改变原椭圆形状，不能宣称保留真实偏心率。

近观构图使用以下近似几何：

~~~text
画面在距离 d 处的高度 H = 2d·tan(f/2)
要求行星直径 B ≈ H/4
抵达距离 d = 2B/tan(f/2)
~~~

因此抵达球体约占画面高度 25%。它是为了看清球体的构图约定，不是真实轨道飞船的安全距离计算。

代码位置：solarsystem.js 的 solveKepler、positionAt、compressA、worldRadius、closeDistance，以及 solar-app.js 的时间推进。

## 11. 核对时看哪些文件

数学工具在 rel.js 与 solarsystem.js，实际显卡代码在 shaders.js，连接相机和参数的代码在 solar-app.js。解释任何公式时，都应核对“定义、代码调用、实际检查”三者。
